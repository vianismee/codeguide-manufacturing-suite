# PAWGLOW Manufacturing System App Flow Document

## Onboarding and Sign-In/Sign-Up
When a new manufacturing user arrives at the PAWGLOW app, they are greeted by a clean landing page that briefly explains how the system helps manage materials, formulas, and product costs. From this page, the user can click the sign-up button to begin creating their account. The sign-up screen allows the user to register with an email and password or to choose a supported social login method such as Google or GitHub via Clerk’s authentication flow. Once they enter their credentials or grant social permissions, they are prompted to set up their company profile by providing a company name, basic contact information, and choosing a subscription plan through Stripe checkout.

After completing their purchase, the user receives a confirmation email and is automatically signed in. The sign-in page is available for returning users, who simply enter their email and password or use the same social login options. If a user ever forgets their password, they can click the “Forgot Password” link, enter their email address, and receive a secure reset link to create a new password. Signing out is as simple as clicking the profile menu in the header and choosing “Log Out,” which ends the session and returns the user to the sign-in screen.

## Main Dashboard or Home Page
Upon signing in, the user is taken to the main dashboard, which presents an overview of the company’s manufacturing data. At the top, a header displays the company name, a notification bell icon, and a profile menu. Down the left side, a fixed sidebar lists the key modules: Inventory, Formulations, Products, Billing, and Settings. The central area of the screen shows summary widgets such as total raw materials, number of saved formulas, active finished products, and the current subscription status. This dashboard acts as the central hub, and clicking on any sidebar item seamlessly navigates the user to that feature’s dedicated page.

## Detailed Feature Flows and Page Transitions
### Inventory Management Flow
When the user clicks on Inventory in the sidebar, they arrive at the materials overview page. Here, they see a table of existing material categories and their unique prefixes. To create a new category, they click the “New Category” button and fill in a name and prefix in a modal form. Upon submission, a server action validates the data, enforces row-level security, and writes the new category to the Supabase database. The updated category instantly appears in the table thanks to TanStack Query’s real-time data syncing.

Within the same Inventory module, the user can switch to the raw materials list. By clicking “Add Material,” they open a form where they select a category, enter the material’s name, unit cost, and unit of measure. A server action then automatically generates a code using the category prefix and the next available sequence number. Once the material is saved, the table reloads to include the new entry.

### Formulation Creation and Version Control
Selecting Formulations from the sidebar takes the user to a page listing all recipe versions. To build a new formula, they click “New Formula,” which brings up a dynamic form interface. The user enters a formula name and then adds ingredients one by one, searching from the inventory, specifying percentage contributions, and adjusting quantities. Client-side validation ensures ingredient percentages sum to 100 before allowing submission. When the formula is saved, a secure server action writes the record to Supabase, creates a new version entry, and returns the updated list. The user can click any formula version to view its details, edit ingredient ratios, or roll back to a previous version.

### Product Definition and Automated COGS Calculation
From the Products menu, the user sees a list of finished goods. To define a new product, they choose “New Product,” where they select a specific formula version, assign a net weight, and choose packaging and labels from the inventory. As soon as they confirm these selections, the system runs a server-side COGS utility. This function fetches all ingredient costs and packaging costs from Supabase, prorates them by weight and percentage, and calculates the final cost of goods sold. The resulting COGS is displayed in a preview and automatically saved to the products table when the user clicks “Confirm.” The product list then updates instantly, showing the new product alongside its computed COGS.

### Payment and Subscription Management
If the user clicks on Billing in the sidebar, they see their current subscription plan, billing cycle, and payment history. To upgrade or change plans, they click the “Change Plan” button, which launches a Stripe checkout session. After completing the payment, a Stripe webhook notifies the app, and the user’s subscription status updates in real time. If a payment fails or the subscription lapses, the Billing page displays an alert and provides a link back to Stripe’s payment form to resolve any issues. Access to Inventory, Formulations, and Products remains enforced by middleware that checks active subscription status.

## Settings and Account Management
In the Settings section, users can manage personal and company profiles. A simple form lets them update their name, email address, and password. Below that, there is a section for notification preferences where they can toggle email alerts for actions such as formula updates or billing events. Further down, company administrators can update address, tax information, and team member roles. Changes are processed via server actions that write to the Supabase database and reflect immediately in the UI. From any settings page, a user can navigate back to the dashboard using the sidebar or click the logo in the header.

## Error States and Alternate Paths
If a user attempts to sign in with incorrect credentials, a clear error message appears under the form field explaining the mismatch and suggesting a password reset. During sign-up, if the email is already in use, the system warns the user to try resetting their password instead. Whenever the app loses network connectivity, a banner appears at the top of the screen alerting the user and offering a retry button. In Inventory and Formulation forms, inline validation prevents invalid input such as missing required fields or ingredient percentages summing to more or less than 100. If a user without an active subscription attempts to access core pages, they are redirected to the Billing page with a prompt to choose or renew a plan. Should the COGS calculation fail on the server, a toast notification explains that an error occurred and suggests trying again or contacting support.

## Conclusion and Overall App Journey
Overall, the PAWGLOW Manufacturing System guides a user from discovering the app on a landing page through signing up with Clerk and subscribing via Stripe, to logging in and navigating a clear sidebar of Inventory, Formulations, Products, Billing, and Settings. Users define material categories, manage raw ingredients, build and version formulas, and link those formulas to finished products with automated cost calculations. Throughout the experience, real-time updates keep data fresh, and robust error handling ensures users can recover from mistakes or connectivity issues. From the first sign-up to daily operations, every step is connected, empowering manufacturing teams to reliably manage workflows and calculate production costs.
